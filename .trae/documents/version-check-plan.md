# 项目模块版本检查计划

## 概述

本计划旨在对 Finetune Platform 项目中的所有模块进行全面的版本检查，确认各模块当前版本是否符合项目要求，识别潜在的版本冲突和不兼容问题。

## 项目依赖结构

项目包含以下三个主要依赖配置：

| 位置 | 文件 | 类型 | 说明 |
|------|------|------|------|
| `client/package.json` | 前端依赖 | npm | React + TypeScript + Ant Design |
| `package.json` | 根目录 | npm | Electron 桌面应用 |
| `server/requirements.txt` | 后端依赖 | pip | FastAPI + PyTorch + Transformers |

## 执行步骤

### 步骤 1：检查前端依赖版本 (client/)

**命令：**
```bash
cd client && npm list --depth=0
```

**检查内容：**
- 对比 `package.json` 中声明的版本范围与实际安装版本
- 识别未在 `package.json` 中声明但已安装的依赖
- 检查是否有已弃用或过时的包

**关键依赖检查：**
| 依赖 | 声明版本 | 最新稳定版 | 状态 |
|------|----------|------------|------|
| react | ^18.2.0 | 18.x | 待检查 |
| antd | ^5.12.0 | 5.x | 待检查 |
| framer-motion | ^12.36.0 | 12.x | 待检查 |
| react-markdown | ^10.1.0 | 10.x | 待检查 |
| recharts | ^3.7.0 | 3.x | 待检查 |
| zustand | ^4.4.7 | 4.x | 待检查 |
| vite | ^5.0.8 | 5.x | 待检查 |
| typescript | ^5.3.3 | 5.x | 待检查 |

### 步骤 2：检查前端过时依赖

**命令：**
```bash
cd client && npm outdated
```

**输出说明：**
- Current: 当前安装版本
- Wanted: 符合 package.json 范围的最新版本
- Latest: 最新稳定版本

### 步骤 3：检查前端安全漏洞

**命令：**
```bash
cd client && npm audit
```

**目的：** 识别已知安全漏洞的依赖版本

### 步骤 4：检查后端 Python 依赖版本 (server/)

**命令：**
```bash
cd server && pip list --format=columns
```

**检查内容：**
- 对比 `requirements.txt` 中指定的版本与实际安装版本
- 识别版本不匹配的包

**关键依赖检查：**
| 依赖 | 声明版本 | 当前安装 | 状态 |
|------|----------|----------|------|
| fastapi | 0.109.0 | 待检查 | 待检查 |
| torch | 2.1.2 | 待检查 | 待检查 |
| transformers | 4.36.2 | 待检查 | 待检查 |
| peft | 0.7.1 | 待检查 | 待检查 |
| accelerate | 0.25.1 | 待检查 | 待检查 |
| bitsandbytes | 0.41.3 | 待检查 | 待检查 |
| pydantic | 2.5.3 | 待检查 | 待检查 |

### 步骤 5：检查 Python 依赖过时情况

**命令：**
```bash
cd server && pip list --outdated --format=columns
```

### 步骤 6：检查 Python 依赖安全漏洞

**命令：**
```bash
pip install pip-audit
pip-audit
```

### 步骤 7：检查根目录 Electron 依赖

**命令：**
```bash
npm list --depth=0
npm outdated
```

**关键依赖检查：**
| 依赖 | 声明版本 | 最新稳定版 | 状态 |
|------|----------|------------|------|
| electron | ^28.1.0 | 28.x | 待检查 |
| electron-builder | ^24.9.1 | 24.x | 待检查 |
| concurrently | ^8.2.2 | 8.x | 待检查 |

### 步骤 8：验证依赖兼容性

**前端兼容性检查：**
- React 18 与 Ant Design 5 的兼容性
- React Router DOM 6 与 React 18 的兼容性
- TypeScript 5.3 与各库类型定义的兼容性
- Vite 5 与 React 18 的兼容性

**后端兼容性检查：**
- PyTorch 2.1.2 与 Transformers 4.36.2 的兼容性
- PEFT 0.7.1 与 Transformers 的兼容性
- bitsandbytes 与 PyTorch CUDA 版本的兼容性
- FastAPI 0.109.0 与 Pydantic 2.5.3 的兼容性

### 步骤 9：识别版本冲突

**检查项：**
1. 前端 peer dependencies 冲突
2. Python 依赖版本冲突
3. 跨项目依赖版本不一致（如共享的配置文件）

### 步骤 10：生成版本检查报告

**报告内容：**
1. 执行摘要
2. 前端依赖状态表
3. 后端依赖状态表
4. Electron 依赖状态表
5. 版本冲突列表
6. 安全漏洞列表
7. 更新建议（包含具体版本号）
8. 降级建议（如有必要）

## 注意事项

1. **执行环境**: 确保在正确的目录下执行命令
2. **网络连接**: 部分检查需要访问 npm/pypi 仓库
3. **虚拟环境**: Python 检查应在正确的虚拟环境中执行
4. **权限**: 某些命令可能需要管理员权限

## 执行顺序

1. ✅ 步骤 1-3: 前端依赖检查（并行执行）
2. ✅ 步骤 4-6: 后端依赖检查（并行执行）
3. ✅ 步骤 7: Electron 依赖检查
4. ✅ 步骤 8-9: 兼容性和冲突分析
5. ✅ 步骤 10: 生成报告
