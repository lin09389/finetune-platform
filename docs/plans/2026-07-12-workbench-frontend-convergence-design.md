# Workbench 前端对齐与视觉收敛设计

日期：2026-07-12
状态：Accepted for implementation

## 产品目标

阶段 7.5 不增加新的 Agent 后端能力。它把阶段 0–7 已经存在的 Workspace、Build/Train/Hybrid、审批、终端、Diff、任务计划、子 Agent、训练活动、恢复与诊断收敛到一套清晰的 Codex 式任务工作台体验。

核心叙事保持不变：用户进入一个项目，输入任务，观察执行，在必要时介入，并审阅代码或训练结果。

## 视觉基线

必须延续现有设计系统：

- Newsreader/Lora/Poppins/Geist Mono 的既有字体角色。
- terra-cotta 强调色、暖白纸面、低对比边框和安静阴影。
- 8–24px 既有圆角层级和 4px 间距节奏。
- `motion-tokens.ts` 的短距离、低幅度动效与 reduced-motion 降级。
- Ant Design 图标与现有 Empty/Loading/Status 组件。

禁止引入新色板、新字体、新图标库、大面积渐变、霓虹、高模糊玻璃、手绘 SVG 或全局 CSS 换肤。

## 信息架构

Workbench 的优先级固定为：

1. **主任务**：任务标题、状态、时间线、输入与下一步。
2. **需要介入**：审批、权限、失败恢复和人工复核。
3. **工程结果**：文件、Diff、终端、验证、产物。
4. **专业工具**：训练活动、子 Agent、环境与诊断。

桌面端仍保留会话栏 + 主任务 + 右侧辅助面板，但在有限宽度下优先收起低优先级面板。移动端同一时间只让一个辅助抽屉覆盖主内容，新任务和切换会话后返回主任务。

## 任务输入区

- 未选 Workspace 时，把 Workspace 选择明确为第一步，并解释发送按钮为何不可用。
- Build/Train/Hybrid 保留为同一任务模式，不新增独立首页。
- Agent 选择、快捷键与发送操作保持当前行为；视觉上降低次要选择器权重。
- 运行中、等待介入、已完成和失败时使用同一输入框骨架，只改变明确的状态提示。
- 不把配置项继续堆入 composer；高级设置仍进入设置抽屉。

## 会话与辅助面板

- 会话列表突出标题和当前状态，时间、置顶、操作属于次级信息。
- 重复历史错误不应与当前错误使用同等权重。
- Diff/终端/任务中心的空状态使用紧凑版本，避免四个大插画争夺注意力。
- 辅助面板标题、Tab、关闭和 resize 行为保持一致；组件内部可迁移到 scoped CSS module，但共享 token 仍是权威。

## 能力对齐标准

每项阶段 0–7 能力都必须回答：

- 用户在哪里发现它？
- 能否从任务上下文直接操作？
- 运行中和失败时看到什么？
- 刷新后是否恢复？
- 是否有桌面/窄屏和主题测试？

阶段 7.5 分两波：

1. **Workbench 收敛**：完整处理默认任务入口、所有运行状态、会话栏、Diff、终端、任务中心与响应式布局。
2. **应用壳与主要页面收敛**：统一 Sidebar/Header/Mobile navigation 的命名和层级，并让 Dashboard、Models、Datasets、Training、Inference、Knowledge、Workspace 等 GA/Beta 主入口采用一致的加载、空、错误和状态组件。

实验能力只做导航分层和守卫一致性，不重做实验页面；团队版导航仍留给后续阶段。第二波不得为了统一而抹平训练、模型和知识库页面各自需要的专业信息密度。

## 验收

- 1440×900、1280×720、390×844 三档视口无裁切和不可达主操作。
- 浅色与深色主题均复用语义 token，无白色 alpha 假设。
- 新任务、运行、等待介入、失败、完成、断线/刷新六类状态都有清晰主行动。
- 键盘焦点、44px 触控目标、可读标签和 reduced-motion 不退化。
- 关键 Workbench Vitest、typecheck、生产构建和 bundle budget 通过。
- 主线程使用相同视口截图进行前后对照；仅测试通过不能视为视觉验收完成。
