训练模块问题分析与修复方案

 ## 发现的主要问题

 ### 1. 启动训练端点参数缺失 ⚠️ 严重
 **位置**: `server/api/training.py:2103-2264`

 **问题**:
 ```python
 @router.post("/start", response_model=TrainingRecordResponse)
 async def start_training(config: TrainingConfigInput):
     # 使用了未定义的变量
     if not skip_resource_check:  # ❌ 未定义
     if use_queue:  # ❌ 未定义
     task_priority = priority_map.get(priority.lower(), ...)  # ❌ 未定义
 ```

 **影响**: 函数无法正常运行，会抛出 `NameError`

 **修复方案**:
 ```python
 @router.post("/start", response_model=TrainingRecordResponse)
 async def start_training(
     config: TrainingConfigInput,
     skip_resource_check: bool = False,
     use_queue: bool = False,
     priority: str = "normal"
 ):
 ```

 ---

 ### 2. LoRA 配置未使用用户参数 ⚠️ 严重
 **位置**: `server/api/training.py:299-326`

 **问题**:
 ```python
 lora_config = LoraConfig(
     task_type=TaskType.CAUSAL_LM,
     r=8,  # ❌ 硬编码，应该使用 config.rank
     lora_alpha=16,  # ❌ 硬编码，应该使用 config.alpha
     lora_dropout=0.1,  # ❌ 硬编码，应该使用 config.lora_dropout
     target_modules=[...],  # ❌ 固定模块，应该根据 config.target_modules 动态设置
 )
 ```

 **影响**: 用户设置的 LoRA 参数完全无效，无法控制微调效果

 **修复方案**:
 ```python
 # 根据 target_modules 配置选择目标模块
 if config.target_modules == "all":
     target_modules = ["q_proj", "v_proj", "k_proj", "o_proj",
                      "gate_proj", "up_proj", "down_proj"]
 elif config.target_modules == "attn":
     target_modules = ["q_proj", "v_proj", "k_proj", "o_proj"]
 elif config.target_modules == "mlp":
     target_modules = ["gate_proj", "up_proj", "down_proj"]
 else:
     target_modules = config.target_modules.split(",")

 lora_config = LoraConfig(
     task_type=TaskType.CAUSAL_LM,
     r=config.rank,
     lora_alpha=config.alpha,
     lora_dropout=config.lora_dropout,
     target_modules=target_modules,
     bias="none",
     inference_mode=False,
 )
 ```

 ### 4. 检查点恢复逻辑错误 ⚠️ 严重
 **位置**: `server/api/training.py:293-296`

 **问题**:
 ```python
 if resume_from and os.path.exists(resume_from):
     model = PeftModel.from_pretrained(model, resume_from)
     model.merge_and_unload()  # ❌ 这会丢失 LoRA 权重！
     # 然后重新初始化 LoRA，导致无法恢复
 ```

 **影响**: 断点续训功能完全失效

 **修复方案**:
 ```python
 if resume_from and os.path.exists(resume_from):
     logger.info(f"从检查点恢复：{resume_from}")
     # 直接加载 PEFT 模型，不要 merge
     model = PeftModel.from_pretrained(model, resume_from, is_trainable=True)
 else:
     # 新建 LoRA 配置
     lora_config = LoraConfig(...)
     model = get_peft_model(model, lora_config)
 ```

 ### 5. 数据集格式支持不足 ⚠️ 中等
 **位置**: `server/api/training.py:341-398`

 **问题**: 只支持 messages 格式，不支持其他常见格式

 **修复方案**:
 ```python
 def format_conversation(example):
     # 支持多种格式
     if "messages" in example:
         # ChatML 格式
         messages = example["messages"]
         text = ""
         for msg in messages:
             role = msg.get("role", "")
             content = msg.get("content", "")
             if role == "user":
                 text += f"User: {content}\n"
             elif role == "assistant":
                 text += f"Assistant: {content}\n"
         return {"text": text}
     elif "instruction" in example:
         # Alpaca 格式
         instruction = example["instruction"]
         input_text = example.get("input", "")
         output = example.get("output", "")
         if input_text:
             text = f"Instruction: {instruction}\nInput: {input_text}\nResponse: {output}"
         else:
             text = f"Instruction: {instruction}\nResponse: {output}"
         return {"text": text}
     elif "text" in example:
         # 纯文本格式
         return {"text": example["text"]}
     else:
         raise ValueError(f"不支持的数据格式: {example.keys()}")
 ```

 ### 6. 显存优化未实际应用 ⚠️ 中等
 **位置**: `server/api/training.py:1010-1073`

 **问题**: `_apply_memory_preset` 函数设置了配置，但这些配置没有真正应用到训练中

 **影响**:
 - `use_flash_attn` 设置了但没有启用 Flash Attention
 - `deepspeed_stage` 设置了但没有配置 DeepSpeed
 - `offload_optimizer` 设置了但没有启用 CPU Offload

 **修复方案**: 需要在 `TrainingArguments` 中添加 DeepSpeed 配置，并在模型加载时启用 Flash Attention

 ---

 ### 7. 进度更新频率过低 ⚠️ 轻微
 **位置**: `server/api/training.py:518-520`

 **问题**:
 ```python
 if (self.current_step - self.last_update_step) >= self.update_interval:
     self._update_progress(...)
 ```

 **影响**: 用户可能看不到实时进度更新

 **建议**: 降低 `update_interval` 或提供配置选项
